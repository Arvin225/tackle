## Context

当前音乐播放器应用基于React + TypeScript + Vite构建，使用Zustand进行状态管理，Tailwind CSS进行样式设计。应用遵循Apple设计语言，但在交互设计方面存在严重缺陷：

1. **导航缺失**：应用有多个页面（主页、音乐库、播放列表、设置），但没有导航系统
2. **首次使用体验差**：新用户无法找到WebDAV配置入口
3. **逻辑错误**：主页"Browse Library"按钮尝试播放不存在的音乐
4. **WebDAV配置不完整**：useWebDAV hook缺少配置持久化功能
5. **类型错误**：项目存在大量TypeScript类型错误

应用当前在本地运行（http://localhost:5174），但用户无法正常使用核心功能。

## Goals / Non-Goals

**Goals:**

1. 提供清晰的应用级导航，让用户能在所有页面间自由切换
2. 为新用户提供引导式首次使用体验，确保能成功配置WebDAV
3. 修复现有交互逻辑错误，确保按钮行为符合用户期望
4. 实现WebDAV配置的持久化存储，避免用户重复配置
5. 遵循Apple人机界面指南，提供一致、直观的交互体验
6. 保持现有Apple设计语言和视觉风格的一致性

**Non-Goals:**

1. 不重写现有音频播放核心功能
2. 不改变现有数据模型和存储结构（除非必要）
3. 不添加新的第三方依赖（尽量使用现有技术栈）
4. 不改变现有路由结构（只添加导航组件）
5. 不解决所有TypeScript类型错误（只修复与交互相关的错误）

## Decisions

### 1. 导航系统设计

**决策**：采用顶部导航栏而非侧边栏
**理由**：

- 顶部导航更符合Apple Music等现代音乐应用的设计模式
- 移动端友好，可转换为底部导航
- 更节省屏幕空间，适合音乐播放器的主内容区域
- 现有设计没有侧边栏结构，顶部导航集成更简单

**备选方案**：

- 侧边栏导航：提供更多空间但占用内容区域
- 底部导航：更适合移动端但桌面端体验不佳

### 2. 首次使用体验设计

**决策**：采用状态感知的渐进式引导
**理由**：

- 根据应用状态动态调整界面，提供上下文相关的引导
- 避免强制性的全屏向导，减少用户干扰
- 允许用户跳过引导，直接访问设置

**实现方案**：

- 添加`useAppState` hook管理应用状态（首次使用、WebDAV配置状态）
- 在HomePage中根据状态显示不同的UI
- 未配置时显示突出的配置引导卡片

### 3. WebDAV配置持久化

**决策**：扩展LocalStorageService以支持WebDAV配置存储
**理由**：

- 重用现有的LocalStorageService，保持代码一致性
- 本地存储足够安全，不涉及敏感服务器通信
- 简单可靠，无需额外依赖

**实现方案**：

- 在LocalStorageService中添加WebDAV配置的CRUD方法
- 修改useWebDAV hook使用持久化存储
- 添加配置验证和错误处理

### 4. 状态管理架构

**决策**：创建新的`useAppStore`管理应用级状态
**理由**：

- 分离关注点：播放状态、库状态、应用状态
- 避免污染现有的usePlayerStore和useLibraryStore
- 提供清晰的状态管理边界

**状态包括**：

- `isFirstVisit`: 是否首次访问
- `webdavConfigured`: WebDAV是否已配置
- `showSetupGuide`: 是否显示设置引导
- `currentView`: 当前活动视图

### 5. 路由守卫设计

**决策**：不实现严格的路由守卫，采用软引导
**理由**：

- 音乐播放器不是敏感应用，不需要强制配置
- 软引导提供更好的用户体验，允许用户自由探索
- 简化实现，避免路由复杂性

**实现**：

- 在导航组件中根据状态显示提示
- 在相关页面显示上下文引导
- 允许用户访问所有页面，但未配置时显示引导

## Risks / Trade-offs

### 风险1：导航组件与现有设计不协调

**缓解**：严格遵循现有Apple设计语言，使用相同的颜色、间距和动画

### 风险2：状态管理复杂度增加

**缓解**：保持状态简单，只管理必要的应用级状态，避免过度工程化

### 风险3：WebDAV配置持久化安全性

**缓解**：本地存储仅用于非敏感配置，密码等敏感信息可考虑加密或让用户每次输入

### 风险4：首次使用引导干扰现有用户

**缓解**：添加"不再显示"选项，尊重用户选择

### 风险5：性能影响

**缓解**：导航组件使用React.memo优化，状态更新使用选择器避免不必要的重渲染

### 权衡：

- **简单性 vs 完整性**：选择实现最小可行方案，避免过度设计
- **引导强度 vs 用户自由**：采用软引导，平衡指导性和自由度
- **立即修复 vs 长期重构**：优先修复最严重的交互问题，暂不重构整体架构
